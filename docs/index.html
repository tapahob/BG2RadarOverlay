BG Radar Overlay

Self-hosting the relay

Run your own relay server so viewers can summon creatures into your game with Bits or Channel Points — end to end, from an empty Twitch Developer Console to a working panel.

Before you start

The Twitch integration needs a small server sitting between the overlay running on your PC and your viewers' browsers. Your PC never accepts connections from viewers; the relay does, and it passes summons back down.

You may not need this. If somebody has already given you a relay URL and an extension to install, put that URL into the overlay and the extension's config page and you're done. Host your own if you'd rather not depend on someone else's server, or if you want to run one for several streamers.

One relay serves any number of streamers. Nothing about a particular channel is baked into it. Each overlay tells the relay which Twitch channel it belongs to when it connects, and balances, prices and tokens are tracked per channel from there.

Hosting the relay means hosting the extension too

This is the part that surprises people, so it's worth understanding before you spend time on anything else.

The extension secret signs every token that extension deals with, on every channel it runs on. Whoever holds it can mint a token for any of those channels. So nobody can hand you theirs, and you can't point your own relay at somebody else's published extension — the signatures wouldn't match.

Which means self-hosting is really two things: your own Twitch Extension (Part 1) and your own relay server (Part 2).

Your viewers can't see a test extension. While yours is in Local Test or Hosted Test, only accounts on its testing allowlist get the panel — everyone else sees nothing on your stream at all. The allowlist is small (Twitch caps it at around 50 accounts), so it is fine for trying things out and useless for a live audience.

To reach your actual viewers, the extension has to be submitted for Twitch review and Released. Budget for that: review takes days, not minutes, and Twitch can come back with changes they want. Everything else in this guide works while you wait — set the whole thing up in Hosted Test with yourself allowlisted, confirm it works end to end, then submit.

What you need

  • A server with a public IP that can hold ports 80 and 443 — any small VPS is plenty.
  • A domain name pointing at it. Not optional: Twitch only talks to an https:// relay and won't deliver events to a self-signed certificate.
  • A Twitch account, and the Developer Console.

Port 443 is not negotiable. Twitch refuses to deliver Channel Points events to a callback on any other port. If something else on the server already owns 443, you can still do this — see Already running a web server.

Throughout this guide, replace relay.example.com with your own domain.

Part 1 · TwitchCreate the extension

1

Create it in the Developer Console

Go to Developer Console → Extensions and click Create Extension. Give it a name — this is what viewers see, so something like "Summon Creatures" works.

When asked which types it supports, tick Video - Fullscreen and/or Video - Overlay. The panel draws itself over the video.

2

Upload the files and set the paths

On the new version's Asset Hosting section, choose to upload your own files and upload Extension.zip from TwitchIntegration/Extension/ in the repository.

Then set the paths Twitch asks for:

FieldValue
Video Overlay Pathvideo_overlay.html
Config Pathconfig.html

You'll also be asked for icons and a screenshot; the repository has some under TwitchIntegration/Extension/icons/ you can use or replace.

3

Allowlist your relay domain

In the extension's Capabilities settings, find the allowlist for URL fetching domains and add your relay's domain:

relay.example.com

Do not skip this, and check it first if anything breaks. Twitch runs extensions under a Content Security Policy. If your domain isn't on this list, every request the panel makes to your relay is blocked before it leaves the browser — with no error anyone will see. The panel simply sits there looking as though the stream isn't live. It is the single most common reason a correctly-built relay appears dead.

4

Turn on Bits (optional)

If you want viewers to buy summon tokens with Bits, open the Monetization settings, enable Bits, and add at least one Bits Product.

The price doesn't matter much — viewers pick a listed product, and the relay works out how many tokens that is from the exchange rate you'll set later. One product at 100 Bits is a fine start.

Skip this if you only want Channel Points.

5

Collect the extension's secrets

Still in the extension's Manage area, you need three values. Two of them are both called some kind of "secret", which is the usual place to go wrong:

WhereGoes into
The Secret — a long base64 string, usually behind a button that generates one TWITCH_EXTENSION_SECRET
The extension's Client ID TWITCH_EXTENSION_CLIENT_ID
The extension's Client Secret — a different field from the Secret above, on the same page TWITCH_EXTENSION_CLIENT_SECRET

Keep them somewhere for a minute; you'll paste all of them into one file in step 9.

The first one signs every token the extension deals with. The other two let your relay read the prices you save on the config page. Different jobs, same page.

Part 1 · TwitchRegister the OAuth Application

This step is only needed for Channel Points. Skip it if you only want Bits, and leave the two variables blank in step 9.

It is a separate registration from the extension — a different thing in the Developer Console, with its own client ID and secret. The extension's own credentials can't create the event subscription that tells your relay when someone redeems a reward.

6

Create an Application and point it at your relay

Go to Developer Console → Applications and click Register Your Application.

FieldValue
NameAnything — My Radar Relay
OAuth Redirect URLshttps://relay.example.com/oauth/callback
CategoryApplication Integration
Client TypeConfidential

Save, then copy the Client ID, and use New Secret to generate a Client Secret. These become TWITCH_CLIENT_ID and TWITCH_CLIENT_SECRET.

The redirect URL must match exactly. Character for character: https://, your domain, /oauth/callback, no trailing slash and no port number. Your relay builds the same URL from the domain you give it, and Twitch rejects the whole exchange if the two differ by so much as a slash.

Register your own — don't ask to be added to someone else's. An Application can hold several redirect URLs, so in principle somebody could add yours to theirs. It would also mean sharing their client secret with you, which hands you the ability to complete OAuth flows as them. Registering your own takes a minute and costs nothing.

Part 2 · ServerSet up the server

7

Install Docker

On a fresh Ubuntu or Debian server:

# Docker itself, plus the compose plugin - Ubuntu's docker.io
# package does not include compose, which trips people up later.
sudo apt update
sudo apt install -y docker.io docker-compose-v2

Check both are there:

docker --version && docker compose version

Also make sure your domain's DNS A record points at this server's IP before going further — the certificate can't be issued until it does.

8

Get the code

sudo git clone https://github.com/tapahob/BG2RadarOverlay.git /opt/bg2radar-relay
cd /opt/bg2radar-relay/TwitchIntegration/Relay/docker

Everything from here happens in that docker folder.

9

Fill in the environment file

Copy the template and open it:

sudo cp .env.example .env
sudo chmod 600 .env
sudo nano .env

Fill in the values you collected in steps 5 and 6:

# Your domain, without https:// and without a port.
RELAY_DOMAIN=relay.example.com

# From the extension (step 5).
TWITCH_EXTENSION_SECRET=the-long-base64-secret
TWITCH_EXTENSION_CLIENT_ID=your-extension-client-id
TWITCH_EXTENSION_CLIENT_SECRET=your-extension-client-secret

# From the Application (step 6). Leave both empty for Bits-only.
TWITCH_CLIENT_ID=your-application-client-id
TWITCH_CLIENT_SECRET=your-application-client-secret

You don't set the redirect URL here. The relay builds https://RELAY_DOMAIN/oauth/callback from the domain, which is exactly what you registered in step 6 — one place to get it wrong instead of two.

Three of these are secrets. Keep .env at mode 600 and never commit it. The repository ignores it by default.

10

Start it

sudo docker compose up -d

This builds the relay and starts it behind Caddy, which gets a real certificate for your domain on first run. Give it a few seconds, then check:

curl https://relay.example.com/health

It should print OK. If it does, the relay is live and reachable from the internet, with a valid certificate. sudo docker compose ps should also show the relay as healthy.

Part 3 · ConnectPoint everything at it

11

The overlay app

In BG Radar Overlay, open Options → Twitch Integration and set:

FieldValue
Twitch IntegrationEnabled
Relay Server URLhttps://relay.example.com
Twitch Channelyour channel login, e.g. yourname

Then press Generate. It creates a stream key, saves it, and connects — the status should go to Connected, and the button becomes Connect for next time.

Copy that stream key; you need it in the next step.

12

The extension's config page

Install your extension on your own channel, then open its configuration page from the Twitch creator dashboard and fill in:

FieldWhat to put
Relay Server URLhttps://relay.example.com — the same as in the app
Stream Keythe key from step 11
Bits per Summon Tokene.g. 100. 0 turns Bits off
Channel Points per Summon Tokene.g. 500. 0 turns Channel Points off
Token Reward Namethe exact title of the reward you'll create in step 13
Max Tokens per Vieweroptional ceiling; 0 means no limit

Save. The panel on your stream should start showing your party within a few seconds.

13

Channel Points (optional)

Two things, in this order.

Create the reward. In your Twitch creator dashboard, add a Custom Reward whose title matches the Token Reward Name you typed on the config page, exactly (capitalisation doesn't matter). That is the only reward your relay treats as buying tokens; every other reward on your channel is ignored.

Turn on "Skip Reward Requests Queue" for that reward. Tokens are credited the moment a redemption arrives. If the reward sits in your queue and you refund it later, the relay does take the tokens back — but only if you completed the authorization below. Skipping the queue means the points are final at redemption time and the two can never disagree.

Authorize. Back on the config page, press Authorize Channel Points and approve in the tab that opens. This is the one step each streamer does individually, as themselves.

The config page should then report Channel Points as authorized and active.

Every variable, and where it comes from

VariableWhere to find itNeeded for
RELAY_DOMAIN Your own domain, pointing at the server. No https://, no port. Always
TWITCH_EXTENSION_SECRET Your extension → Manage → the base64 Secret Always
TWITCH_EXTENSION_CLIENT_ID Your extension → Manage → Client ID Always
TWITCH_EXTENSION_CLIENT_SECRET Your extension → Manage → Client Secret (not the Secret above) Always
TWITCH_CLIENT_ID Your Application → Client ID Channel Points
TWITCH_CLIENT_SECRET Your Application → New Secret Channel Points

The relay derives two more URLs from RELAY_DOMAIN so you never type them twice: https://domain/oauth/callback, which must match what you registered on the Application, and https://domain/eventsub/callback, which Twitch posts redemptions to.

Backups and updates

Everything that has to survive a restart lives in a Docker volume called relay-data: token balances viewers paid real Bits for, each streamer's authorization, spent transaction records, and the secret Twitch signs events with.

docker compose down -v deletes it — and that is worse than it sounds. Losing balances is the obvious part. The quiet part is the event secret: the relay generates a new one, every subscription already registered with Twitch keeps signing with the old one, and from then on every Channel Points redemption is rejected while Twitch still reports everything as healthy. Nothing looks broken. Redemptions just stop crediting.

If that happens, each affected streamer presses Authorize Channel Points again, which rebuilds their subscriptions with the current secret.

Back it up instead:

sudo docker run --rm -v relay-data:/data -v "$PWD:/backup" alpine \
  tar czf /backup/relay-data-$(date +%F).tar.gz -C /data .

To update the relay:

cd /opt/bg2radar-relay
sudo git pull
cd TwitchIntegration/Relay/docker
sudo docker compose up -d --build

The volume is untouched, so balances and credentials carry over.

Update the extension at the same time. The relay and the extension are versioned together. A relay expecting something an older installed extension doesn't send will turn purchases away — so re-upload Extension.zip when you pull a new relay.

Already running a web server?

If the server already has nginx, Traefik or another Caddy on 443, use the second compose file instead. It brings up the relay alone, on a loopback port, with no Caddy of its own:

sudo docker compose -f docker-compose.existing-proxy.yml up -d

Then point your existing proxy at 127.0.0.1:5080, making sure it:

  • serves your domain over HTTPS on port 443 with a real certificate;
  • forwards WebSocket upgrades — the overlay opens /ws/ingest/… and holds it open;
  • routes /oauth/callback and /eventsub/callback on port 443 specifically. Everything else can live elsewhere if you have a reason.

Troubleshooting

It works for me, but my viewers don't see the panel at all

The extension is still in a test state. Only accounts on its testing allowlist can see it — which is why it looks fine to you. Submit it for review and get it Released; there is no setting that skips this.

The panel never loads anything, and nothing errors

Almost always the extension's URL-fetching allowlist (step 3). Twitch blocks the request before it leaves the browser, so the panel waits forever. Open the browser console on your own stream — a Content Security Policy violation confirms it.

docker: unknown command: docker compose

Ubuntu's docker.io package doesn't include the compose plugin. sudo apt install docker-compose-v2.

compose exits complaining about a variable

A required entry in .env is empty. The message names which one.

No certificate

Your domain has to already resolve to this server, and ports 80 and 443 have to be free. sudo docker compose logs caddy will say which one is the problem.

The overlay says Error

Check the Relay Server URL matches your domain and that the Twitch Integration tab has a stream key. sudo docker compose logs relay shows connection attempts as they arrive.

Bits purchases fail

Usually TWITCH_EXTENSION_SECRET. Check it's the base64 Secret from the Manage page and not the client secret from the same page — and that it's from your extension.

OAuth says the redirect doesn't match

The Application's registered redirect URL has to equal https://RELAY_DOMAIN/oauth/callback character for character. No trailing slash, no port.

Channel Points redemptions don't credit

Check the config page reports Channel Points as authorized — if it mentions rejected deliveries, press Authorize again. Then confirm the reward's title matches the Token Reward Name field and that Skip Reward Requests Queue is on.
